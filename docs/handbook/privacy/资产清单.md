# 隐私资产与环境隔离

安装依赖见 [ENVIRONMENT.txt](../../../ENVIRONMENT.txt)。本机运行环境留在 zace 内；
凭据集中放在仓库外的 `$HOME/.key/zace/`，root 用户即 `/root/.key/zace/`。

## 1. 文件职责

| 资产 | 位置 | Git | 权限 |
|---|---|---|---|
| API/LLM 凭据 | `$HOME/.key/zace/secrets.env` | 仓库外 | 0600，父目录 0700 |
| SSH 部署密钥 | `$HOME/.key/` 中已有的专用密钥 | 仓库外 | 私钥 0600 |
| 无密钥模板 | `zace/.env.example` | 提交 | 普通文本 |
| 本机配置 | `zace/.env` | 忽略 | 0600 |
| Python / Rust / Web 环境 | `.venv/`、`.local/{cargo,rustup}/`、`web/node_modules/` | 忽略 | 本机文件 |
| 索引、缓存、日志、测试结果 | `zace/.local/` | 忽略 | 本机目录建议 0700 |
| 修改前备份 | `zace/backups/` | 忽略 | 建议 0700 |
| 内部基准资料与清单 | `$HOME/.key/zace/benchmarks/` | 仓库外 | 目录 0700，文件 0600 |
| 硬件参数和脱敏报告 | `configs/profiles/`、`benches/results/` | 提交 | 不含 IP/主机名/Key |

不要用软链接把密钥文件引入仓库。已有软链接需先审查，再决定如何处理。
`.gitignore` 只影响未跟踪文件，不能撤销已跟踪文件或历史记录。

## 2. 初始化与加载

```bash
bash scripts/setup-dev.sh --with-web
set -a; source .env; set +a
```

脚本只创建缺失的空凭据文件，不覆盖已有 Key。通过本机编辑器填写
`$HOME/.key/zace/secrets.env`；`.env` 只加载外部文件。

| 变量 | 来源 | 何时需要 |
|---|---|---|
| `EMBED_API_KEY` | Voyage 等 embedding 供应商 | 真实 API 索引与吞吐测试 |
| `ANSWER_API_KEY` | 配置的 LLM 供应商或自建网关 | `ask_project` 的 LLM 总结 |
| `ANSWER_BASE_URL`、`ANSWER_MODEL` | LLM 服务配置 | 与上述 Key 配套 |
| npm token | npm 签发 | 发布包；不属于运行环境 |
| zace 服务 API Key | 服务内账户创建 | 客户端接入；不是 embedding Key |

供应商密钥丢失时，从原凭据来源恢复或在签发方重签。不能通过本地生成随机字符串恢复。
local-only 探针不需要真实 Key；未配置 `ANSWER_*` 时总结功能明确降级。

## 3. 迁移包

```bash
bash scripts/pack-secrets.sh
```

默认输出为 `$HOME/.key/zace/zace-secrets-<UTC>.tar.gz`，权限 0600。
只打包 zace 的外部 `secrets.env`、本机 `.env`、说明和恢复脚本；
不包含 SSH 私钥、npm 全局凭据、私有基准资料、索引、数据库或其他应用资产。
内部用例和报告需要在授权的私有环境单独迁移；runner 通过 `--targets-file` 显式加载外部清单。
打包脚本拒绝把输出写入 Git 工作树，也拒绝覆盖已有文件。

在目标机器的私有目录解包后：

```bash
bash <私有目录>/zace-secrets/restore.sh <zace仓库绝对路径>
```

恢复脚本先把同名旧文件备份到外部密钥目录，再恢复凭据和本机配置。
默认不修改系统服务、不建立 nginx 链接、不启动服务。
依赖由 `scripts/setup-dev.sh` 安装，生产配置按 [部署手册](../deployment/vps.md) 单独执行。

## 4. 公开与轮转

Key、Cookie、账户数据库、内部源码、请求日志和隐私包不进入提交、Issue、PR 或聊天。
公开性能报告只保留必要规格、配置、版本与计量字段，使用规格别名标识设备。
历史截图和旧报告需要单独审查，不能因为当前配置已隔离就声称整个 Git 历史已脱敏。

若凭据曾泄露，在签发方撤销并重签，再更新外部文件和相应进程。
更换 embedding Key 本身不改变模型/维度指纹，不应因此全量重嵌。
