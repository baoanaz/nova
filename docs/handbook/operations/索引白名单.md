# 索引白名单（让被 `.gitignore` 排除的 AI 文档也进索引）

> 适用版本：TASK-097（Phase 3 / M2c）之后的 core 与 client。
> 本文命令与输出均在 WSL2 Ubuntu / Python 3.12 上实测（`/tmp/task097-real` 与 GitNexus 仓库）。
> 设计依据：`docs/tasks/archive/TASK-097-索引白名单.md`；契约见 `docs/contracts/PROCESS.md` R42/R43。

## 1. 它解决什么问题

nova 的索引范围**跟随 `.gitignore`**。很多项目把 AI 目录写进 `.gitignore`：

```gitignore
.claude/
.codex/
```

于是 `.claude/skills/*/SKILL.md` 这些**信息密度极高**的技能文档永远不会被索引——
你问"这个项目的评审流程是什么"，nova 检索不到唯一的权威文档。

白名单让你把这些文件**强制包含**进来：

```console
$ cat .novainclude          # 可选：项目自定义白名单（每行一个模式）
my-notes
```

```console
$ nova ... # 索引后
.claude/skills/gitnexus-review/SKILL.md   ← 被 gitignore 排除，但被白名单救回
```

## 2. 优先级：它是"第 0 层"，但只压两层

| 层 | 规则 | 方向 | 来源 |
|---|---|---|---|
| **0** | **索引白名单** | **包含**（force-include） | `.novainclude` + 内置默认 + `NOVA_INDEX_ALLOWLIST` |
| 1 | `.novaignore` | 排除 | `{repo}/.novaignore` |
| 2 | `.gitignore` | 排除 | 各层级 `.gitignore` |
| 3 | 内置默认 | 排除 | `DEFAULT_SKIP_DIRS` + `DEFAULT_SKIP_DIR_PATTERNS` |

**关键语义（容易误解，务必读完）**：

1. 命中白名单的路径 → 越过第 1、2 层，**强制索引**；
2. **白名单不压第 3 层**——`.git/objects/**`、`node_modules/**`、`build-*/` 里的文件
   **救不回来**。这不是实现疏漏，而是刻意的硬约束：
   `node_modules/*/skills/a.py` 与你的技能文档只是**同名结构**，把它拖进索引毫无价值；
   `.git/objects` 更是二进制。实测：238 文件的仓库里，`node_modules/pkg/skills/a.py`
   与 `.git/objects/**` **既不被索引、也不被 `scandir` 触碰**；
3. **下钻有界**：`.claude/` 被排除、白名单要救的 `skills/` 住在它下面时，nova 会"进去看一眼"，
   但只在**直接子项命中白名单**时才继续，且连续下钻层数有上限（默认 4 层）。
   一个被排除的 `vendor/`（几百个文件）不会被整棵枚举——实测只 `scandir` 它一次、不进入；
4. **白名单不改阈值**：命中白名单的大文件/二进制文件仍按 R43 跳过，并如实带原因进
   `skipped_files`。白名单管的是"范围"，不是"什么都读"。

## 3. 默认清单（**可以删，不是不可动的硬编码**）

| 类型 | 条目 | 说明 |
|---|---|---|
| 文件名 | `AGENTS.md` | 主流编辑器的项目指令文件 |
| 文件名 | `CLAUDE.md` | Claude 的项目指令文件 |
| 文件名 | `.agent.md` | agent 专用变体 |
| 文件名 | `.cursorrules` | Cursor 规则文件 |
| 文件名 | `HANDOFF.md` | 项目交接文档 |
| 目录名 | `skills` | **任意层级**的 `skills/` 目录下的全部文件 |

说明：

- 文件名匹配**大小写不敏感**：`agents.md` 与 `AGENTS.md` 等价；
- `skills` 是**目录名**规则：`skills/`、`.claude/skills/`、`tools/mine/skills/` 都命中，
  且**不限文件名**（`SKILL.md` 与同目录的参考文档、脚本、模板一起进来）——这是对
  "skill.md 该单独开一个 doctype 吗"的回答：先靠目录规则覆盖，语义上 `SKILL.md` 仍被识别为
  `agent-instructions`（享受既有的 rerank 加分，分值未改）；
- 命中白名单的 `AGENTS.md` / `CLAUDE.md` / `.agent.md` / `.cursorrules` / `HANDOFF.md` /
  `SKILL.md` 会被判定为 `agent-instructions` 文档类型。

## 4. 怎么加自己的条目（"随意添加"）

三种来源**取并集**（不覆盖）：

### 4.1 项目自定义：`{repo}/.novainclude`

每行一个条目，语法刻意收窄（**不是**完整 gitignore 语法）：

```text
# 注释（# 开头）
my-notes          # 目录型：命中任意层级的 my-notes/ 目录
docs/plans/       # 目录型（含 / 一律按目录名处理，取末段 plans）
PROJECT_RULES.md  # 文件名型（含点且不含 / → 按 basename 匹配）
!skills           # ! 取消：把上面（含内置）的 skills 项关掉
```

规则：

| 写法 | 类型 | 匹配方式 |
|---|---|---|
| 含 `/`（如 `my-notes/`、`docs/plans`） | 目录 | 取末段作目录名，命中**任意层级**同名目录及其下全部文件 |
| 不含 `/` 且**不含点**（如 `skills`） | 目录 | 同上 |
| 不含 `/` 且**含点**（如 `AGENTS.md`、`.cursorrules`） | 文件名 | 按 basename，大小写不敏感 |
| `!name` | 取消 | 取消同名的白名单条目（后写覆盖先写） |

**不支持** `*` / `**` / `?` / `[]` 通配：白名单是"我必须拿到这些高价值文件"的显式清单，
引入通配会让它变成第二套 `.gitignore`，两侧（core / client）语义对照立刻失效。
写通配的行会被**静默忽略**（不报错），需要范围排除时请用 `.novaignore`。

优先级：内置默认 < 环境变量 < `.novainclude`（越靠近项目越优先，与第 1/2 层同方向）。
因此 `.novainclude` 里写 `!skills` 能关掉内置的 `skills`——**默认清单是可删的**。

### 4.2 全局：`NOVA_INDEX_ALLOWLIST`

逗号分隔，适合服务端 / CI 统一配置：

```console
$ export NOVA_INDEX_ALLOWLIST="my-notes,docs/plans/"
```

### 4.3 下钻范围（高级）：`NOVA_ALLOWLIST_SCOPE` / `NOVA_ALLOWLIST_DEPTH`

| 取值 | 行为 |
|---|---|
| `deep`（默认） | 被排除的目录中只要有**直接子项**命中白名单就进去（名字定向 + 深度上限）。**能处理 `.claude/` 被排除而 `skills/` 在其下的形态** |
| `gitignored` | 不为被排除的目录下钻；只有"目录**自己**被白名单点名"时才放行（`.gitignore: skills/` + 白名单 `skills`）。上述 `.claude/` 形态**救不到** |
| `shallow` | 完全不进——白名单只压文件级 `.gitignore` 规则，不改变目录剪枝 |

> 选范围前先问自己："被排除的是**哪个**目录？" 排除的是 `skills/` 本身 → 任何范围都能救；
> 排除的是它的**祖先**（`.claude/`、`hacks/`）→ 需要 `deep`（默认值，即默认配置就是对的）。
> 三档都**不**突破内置跳过目录。

`NOVA_ALLOWLIST_DEPTH`（默认 `4`）限制**连续被排除层数**；改大它意味着在被排除的目录树里
多走几层，会变慢。非法取值一律回落默认（打错的环境变量不该让索引起不来）。

## 5. 风险（必读）

> **白名单会突破 `.gitignore`。**

- 你在 `.novainclude` 里写了一条目录规则，就等于把那个目录**及其全部内容**（含可能的
  secret、日志、大文件）纳入上传范围；服务端索引后，这些内容会被切分并**上传到远端**；
- **不要**把 `.env`、`.aws/`、`*.pem`、数据库导出目录之类的路径写进白名单；
- 目录规则不限文件名，所以 `skills/` 会连带索引同目录下的**所有**文件（脚本、模板、
  测试数据）。若只想索引文档，请改用文件名型条目（如 `SKILL.md`）；
- 白名单**不**改变"跳过必须可观测"的纪律：超大/二进制文件仍进 `skipped_files`/`skip_reasons`；
- 白名单**不**突破内置跳过目录；这条边界有专门的回归测试守护（见 §7），
  因为 `skills` 是个通用目录名，`node_modules/*/skills/` 与你的技能目录同名纯属巧合。

## 6. 索引没进去？排查顺序

| 现象 | 原因 | 处理 |
|---|---|---|
| 文件仍被跳过，`reason` 是 `builtin` | 它或它的祖先在内置跳过目录里（`node_modules` / `.venv` / `build-*` …） | **无法救回**（设计如此）；换目录放文档 |
| 目录型白名单没生效 | 该目录被排除，且"直接子项"没有命中白名单 | 检查范围：`NOVA_ALLOWLIST_SCOPE=deep`（默认）应能处理 `.claude/skills` 形态；或写成目录规则 `skills`（不含点）而不是文件名规则 |
| 下钻层级不够 | 连续被排除的层数超过 `NOVA_ALLOWLIST_DEPTH`（默认 4） | 调大该变量，或把父目录也加进白名单 |
| 写了一行含 `*` 的条目但没生效 | 通配被刻意忽略 | 改用 `.novaignore` 做排除，或写显式条目 |
| 文件"看起来进了清单"但内容为空 | 白名单只管**范围**；超限/二进制由 R43 阈值裁决 | 看 `skip_reasons` |

## 7. 实现与守护（给维护者）

| 侧 | 文件 | 做法 |
|---|---|---|
| core（Python，本地模式） | `core/nova_core/pipeline/ignore.py` | `Allowlist` 类 + `IgnoreRules.is_ignored` 的**先判内置、再判白名单**短路；目录下钻在 `pipeline/source.py::DirectorySource._walk` |
| client（Rust） | `client/src/ignore.rs` | `Allowlist` + `walk_union()`（walker A 正常忽略，walker B 关闭忽略规则只做白名单） |

**两侧必须一致（R42）**。已知差异与实现取舍：

1. `ignore` crate 的 `overrides` API **没有**采用：它在"存在至少一条白名单 glob"时会把
   **未命中 glob 的普通文件判为忽略**（`overrides.rs::Override::matched`），
   那会变成"只索引白名单"。client 改为两次遍历取并集（与 core 的两步裁决同构）；
2. `ignore` crate 仍会豁免**被 git 跟踪**的文件（TASK-037 已记录的既有差异，约 1.9%）；
   白名单救回的文件**不在** git 索引里，因此这条差异不影响本卡语义；
3. 对照测试：core `test_allowlist.py::test_parity_fixture_matches_expected_list` 与
   client `tests/allowlist_parity.rs::parity_fixture_matches_expected_list` 持有**同一份**
   夹具与期望清单，两侧任一方语义漂移都会立刻失败；
4. 回归测试：三种关键情形（救回被排除的 `skills/`、**不**救回 `node_modules/**/skills/`、
   **不**救回 `.git/**`）在两侧都有独立断言；
5. 性能：被排除的大目录只在下钻链上、且只在"直接子项命中"时才进入；缓存指纹包含
   `.novainclude`（改了白名单会作废本地缓存，不会继续用旧文件集）。

## 8. 快速自检

```console
$ printf 'my-notes\n' > .novainclude
$ printf 'my-notes/\n' >> .gitignore
$ mkdir -p my-notes && echo '# 待办' > my-notes/todo.md
$ # 索引 / 同步后应能看到 my-notes/todo.md
$ # 反向验证：node_modules 下的同名结构不应出现
$ printf 'x=1\n' > node_modules/pkg/skills/a.py   # 不应被索引
```
