## 0. 组件定位

一句话：**把 ContextPack 压缩成一次有引用、可验证、区分事实与意图的项目级回答**。

```text
User Question + ContextPack（03 产出，≤12K token）
        │
        ├─ answerable=false → 短路：不调 LLM，返回结构化"证据不足"（§3）
        ▼
   1 × Grounded LLM（deepseek-v4-flash，可配置）     ← V1 恰好一次调用
        │
   Citation 回验（§5）→ Answer（1-3K token，带 [E*]/[F*] 引用）
```

**边界**：不管检索（02）、不管装填（03）、不管 LLM 之外任何 I/O；LLM Provider 可插拔（D-11），本组件只依赖 AnswerProvider 接口。

**核心原则**：
> LLM 不负责寻找事实，只负责基于已验证、已整理的证据得出结论。Docs describe intent; Code describes current implementation.

## 1. 设计约束

| # | 约束 | 来源 |
|---|---|---|
| L1 | 总结模型默认 deepseek-v4-flash（OpenAI-compatible，URL/KEY/MODEL 可配置），总结功能整体可选 | D-11 + 已确认业务输入 |
| L2 | ask_project 目标 <10s（60s 为超时上限非目标） | R1（Module/02 §1） |
| L3 | 恰好一次 LLM 调用；不依赖 LLM 主动要求更多源码（要证据先走 02 的 G 表二轮） | 外部建议采纳；服务端行为可控 |
| L4 | 幻觉治理三条硬线：虚构引用 / 虚构调用关系 / Spec 与实现混淆 | Task.md §16 |
| L5 | 未配置 LLM 时 ask_project 功能降级而非报错崩溃 | 开源产品冷启动体验 |

## 2. AnswerProvider 接口与配置

```typescript
interface AnswerProvider {
  complete(req: {
    system: string;
    user: string;
    maxTokens: number;        // 默认 3072
    temperature: number;      // 默认 0.2
  }): Promise<string>;
}
// 配置（服务端环境变量 / 设置页）：
//   ANSWER_BASE_URL   如 https://api.deepseek.com   （base URL，**不要**填到 /chat/completions）
//   ANSWER_API_KEY
//   ANSWER_MODEL      默认 deepseek-v4-flash
//   ANSWER_PROTOCOL   openai（默认）| responses | anthropic     ← D-47
// 未配置 → ask_project 返回 D-26 降级包（§6），search_context 不受影响
```

### 2.1 上游协议（D-47，2026-09-16 追加）

`AnswerProvider.complete()` 的签名**不变**；协议差异只在“发什么包 / 怎么读回复”，
由 `nova_service.llmprotocol` 承担（三种形状集中在一处，见 `test_llm_protocols.py`）：

| 协议 | 端点 | 认证头 | 输出上限字段 | 回复位置 |
|---|---|---|---|---|
| `openai`（默认） | `/v1/chat/completions` | `Authorization: Bearer` | `max_tokens` | `choices[0].message.content` |
| `responses` | `/v1/responses` | `Authorization: Bearer` | `max_output_tokens` | `output[].content[].text`（或 `output_text`） |
| `anthropic` | `/v1/messages` | `x-api-key` + `anthropic-version` | `max_tokens`（必填） | `content[].text`（跳过 `thinking`） |

实时需求（实测 2026-09-16，cviauto 中转网关）：`deepseek-v4-flash` 声明 `ANTHROPIC`/`RESPONSES`、
`deepseek-v4-pro` **仅** `ANTHROPIC`。升级前只实现了 OpenAI Chat Completions，
用户选中这些模型时表现为**保存成功但 `ask` 持续 503**（因为上游不提供该端点）。

三条纪律：

1. **默认协议 = `openai`**：既有部署升级后行为逐字不变（`test_answer.py` 是回归护栏）；
2. **协议错误要可见**：保存端点与启动均校验协议名（非法值 400 / 启动报错），不静默回落；
3. **不自动换协议重发**：一次 ask 只走一条协议（两次计费 + 答案不可归因），
   改协议是用户的显式动作（设置页下拉框，或“测试连接”给出的建议值）。

### 2.2 连接自检（D-47）

`POST /api/auth/llm-config/test` 两级（避免“配错了要到提问才发现”）：

| 级 | 动作 | 能查出 | 成本 |
|---|---|---|---|
| L1（默认） | `GET {base}/v1/models` | key 无效 / 模型名拼错 / 协议不在上游声明里 | 零 token |
| L2（`deep=true`） | 用最小 prompt 真发一次（走选定协议） | “模型列表可见但推理失败”（实测出现过这种形态） | 少量 token |

自检**不写库、无副作用**，测的是**屏幕上正填的那份配置**（适配“改 URL → 测试 → 保存”
这一最自然的顺序）。响应不含 key 的任何部分，上游报错摘要经脱敏截断后不回显给调用方。


deepseek-v4-flash 调用参数表（06 提案正式化）：

| 参数 | 值 | 理由 |
|---|---|---|
| 输入 hardCap | 12K token | 03 已定（D-23）；flash 长输入注意力衰减，宁小勿大 |
| temperature | 0.2 | 调查要事实不要创意 |
| max_tokens | 3072 | answer 是分析+指路，1-3K 足够 |
| 超时 | 60s（连接 10s） | flash 秒级；60s 对齐 Task.md 上限，留二轮检索余量 |

## 3. answerable=false 短路（D-24，与 03 §4.4 联动）

```text
03 判定 answerable=false（无 explicit、无共识、图路径空）
  → 不调 LLM（省一次调用，也避免模型在弱证据上硬编）
  → 直接返回：
     {
       status: "insufficient_evidence",
       bestEffortContext: <ContextPack 的 Markdown 渲染>,   // 有什么给什么
       missingEvidence: [...],                              // 缺什么（03 §5）
       nextQueries: ["TokenService.refresh 的调用方有哪些", ...]  // 怎么补（确定性生成）
     }
```

这让 ask_project 的失败模式是**有用的失败**：agent 拿到部分上下文 + 明确的改问建议，而不是一段幻觉。

## 4. Grounded Prompt（正式版）

```text
System:
你是 nova 项目调查助手。只依据 <evidence> 标签内的内容回答 <question>。

规则：
1. 只能依据 Evidence 回答；不得使用外部知识推测仓库内容
2. 引用格式：[E1] 代码/文档证据，[F1] 调用链证据；每个重要结论必须附引用
3. Code 证据代表当前实现，Doc 证据代表设计意图；两者冲突时必须显式指出
   "实现与设计可能不一致"，并分别列出双方证据，不得只取其一
4. 调用关系只信 [F*] 与证据内容；禁止虚构任何调用关系
5. 证据不足时明确回答"证据不足"并说明缺什么，不要猜测
6. 直接回答问题；不要复述全部证据
7. 用与 <question> 相同的语言回答

User:
<question>…</question>
<context_meta>
confidence: medium        // 03 注入，供参考但不许照抄进答案
index: fresh | stale(2 files)
</context_meta>
<evidence>
[Docs]
[E7] docs/auth.md:30-52 …
[Code]
[E1] src/auth/token_service.py:45-82 …
[Flows]
[F1] A → B → C
</evidence>
```

回答模板（空节自动省略——简单问题数百 token 即可）：

```markdown
## Answer
（直接回答）
## Code Flow          // 有调用链时
## Key Evidence       // 关键证据清单（path:lines）
## Spec vs Implementation   // 检测到意图与实现差异时——nova 的差异化能力
## Missing Evidence   // 仍有缺口时
```

## 5. Citation 回验（D-25）

LLM 返回后在服务端做一次确定性校验（吸收外部建议，成本为零）：

```text
answer 中的 [E\d+]/[F\d+] → 正则抽取
  ├─ id 存在于 ContextPack → 保留
  └─ id 不存在（虚构引用）→ 删除该标记，Missing Evidence 节追加
       "回答中 N 处引用无效已移除"（保留原文，只删标记）
citationCoverage = 有效引用数 / 结论段落数 → 存审计（不惩罚输出，先观察分布）
```

不删整句、不改写——只移除无效标记并注记，保持回答原文的可信边界清晰。

## 6. 失败降级：never empty-handed（D-26）

| 故障 | 行为 |
|---|---|
| LLM 超时 / API 错误（≤2 次重试后） | 返回 ContextPack 的 Markdown 渲染 + 前置说明"总结模型暂时不可用，以下为检索到的上下文包（含 Missing Evidence）" |
| 未配置 ANSWER_* | 同上 + "管理员可在设置中配置总结模型" |
| 配置了但模型名/密钥无效 | 同超时路径（第一次调用即验证） |

ask_project 永不空手而归：最差情况等价于一次 search_context + 明确的故障说明。

## 7. Confidence 注入（LLM 不自评）

最终回答的置信度由引擎侧信号决定（吸收外部建议），prompt 的 context_meta 注入但规则 7 禁止照抄：

```text
HIGH：explicit 命中 + ≥3 共识 + callPaths 完整 + index fresh
LOW ：semantic-only + graph_boundary + index stale
（03 §4.4 已产出，本组件透传）
```

## 8. 审计存档（服务于 02 §7-1 的 golden set）

每次 ask_project 服务端存档（脱敏，**不含源码内容**，只存 evidence id/path/score/引用命中）：

```text
{ query, mode, confidence, citationCoverage, llmLatencyMs,
  evidence: [{id, path, lines, tier, score}], answerTokens, createdAt }
```

保留：每项目最近 1000 条。用途：① rerank 分值校准数据（02 §7-1）；② 后续做输出质量回归的种子集。**这是把运营数据变成检索质量改进燃料的闭环设计。**

## 10. V1 明确不做

| 不做 | 理由 | 何时 |
|---|---|---|
| 多轮 LLM（Agent 式调查循环） | 60s 预算内两次 LLM 调用挤占检索；G 表二轮已覆盖大部分缺口 | V2 评估 |
| 流式输出 | MCP tools/call 请求-响应式，V1 一次性返回 | 协议/客户端有诉求时 |
| LLM rerank | 归 02（V1.5） | — |
| 回答缓存（同 query 直接复用） | freshness 语义复杂，易返回过期答案 | 观察 |
| 多模型并发对比 | 成本×N | — |

## 11. 开放问题

1. **Spec vs Implementation 节的触发率**：prompt 规则 3 依赖 docs 与 code 同时在场——03 的 spec 保底配额（1-2 块）是否足以稳定触发，需实测；不足则需在 03 装填优先级中提升 spec 权重。
2. **中文回答的引用格式**：[E1] 与中文文本的混排是否影响 flash 的引用遵从率——用审计数据（§8 citationCoverage）观察。
3. **温度 0.2 vs 0**：极端确定性（0）有时导致 flash 类模型复读证据原文；0.2 是经验折中，待校准。
